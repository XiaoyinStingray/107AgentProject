\section{引言}
%% ============================================================

当前 AI Agent 系统有以下不足：\textbf{其一}，决策风格停留在 prompt 层面，用户缺乏对 Agent 决策风格的控制，导致人格并未真正影响决策与行动；\textbf{其二}，多 Agent 协作不可信赖，Agent 可能"幻觉交付"，声称完成任务却从未真正执行；\textbf{其三}，在非专业任务场景下，Agent 行为无法量化比较，"谁的 Agent 更好"只能靠主观判断，缺乏客观标准。

Life Lab 正是为应对这三大挑战而设计。其核心理念是：\textbf{你是导演，Agent 是演员。你设定好角色和舞台，按下开始，看他们怎么演。}我们关注的不仅是"Agent 能否完成任务"，更是"当 Agent 拥有了性格、情绪和同伴，会产生什么样的决策倾向"。平台基于\textbf{真实场景}构建（图书馆、宿舍、教室、艺术中心、实验室、樱花大道 6 种场景），贴近学生日常学习与生活，使 Agent 行为更具真实感和说服力。与 AutoGen / CrewAI 侧重任务编排、LangGraph 侧重图编排、AgentBench 侧重黑箱评分不同，Life Lab 的独特定位是\textbf{Agent 社会实验平台}，同时提供人格建模、行为评测和游戏化场景。Life Lab 已积累 \textbf{25 个 Agent、48 个世界实例、47 次模拟运行}，形成了完整的功能闭环。

\section{平台概览与技术架构}
%% ============================================================

Life Lab 构建了一个基于 \textbf{FastAPI + AutoGen + React + Phaser} 的 AI Agent 社会模拟平台。用户用自然语言描述一个角色，例如"来自小镇的计算机系新生，内向但野心大"，系统通过 LLM 自动生成该角色的完整人格，包括MBTI、大五人格、决策风格、价值观、背景故事和层级化目标，并交由用户修改确认。

\section{创新一：人格驱动的社会涌现}
%% ============================================================

\textbf{问题}：现有 Agent 系统的"人格"只是 prompt 中的几个形容词，影响 Agent"说什么"，但不影响"怎么做"。一个"内向"的 Agent 和一个"外向"的 Agent 在同一个虚拟场景中，移动方式、社交频率、情绪变化几乎完全相同。

\textbf{方案}：Life Lab 基于 Phaser 3 构建了 2D 瓦片地图场景并搭建了随机引擎，支持图书馆、宿舍、教室、艺术中心、实验室、樱花大道 6 种场景，将 MBTI 人格参数直接映射为游戏行为，由人格参数直接决定移动频率、探索范围和空闲概率，而非通过 prompt 间接影响：

\begin{itemize}
	\item \textbf{人格驱动移动}：内向型 Agent 移动频率低、范围小、空闲率高；外向型则活跃得多。具体地，内向思考型（I\_T\_）移动间隔 9--16s、最大探索范围 2 格、空闲概率 45\%，外向情感型（E\_F\_）移动间隔 3.5--8s、范围 3 格、空闲概率仅 10\%，行为差异直接可观测。
	\item \textbf{五重情绪引擎}：Agent 的情绪由五种因素共同驱动：对话内容（18 条正则规则匹配 8 种情绪）、环境氛围（6 种场景各有情绪偏向）、附近 Agent 的情绪共鸣（3 格内同频放大/异频中和）、随机事件（25+ 事件池，每 30--70s 触发）、以及自然衰减（每 30s 向中性回归）。三种独立定时器协同工作，使情绪变化具有真实的时间节律。
	\item \textbf{社交涌现}：当两个 Agent 接近到一定距离，自动触发面对面多轮对话，内容由 LLM 根据双方人格实时生成。移动目标选择采用 25\% 物品寻求 + 40\% 社交接近 + 35\% 随机漫游的混合策略，使 Agent 的行为既有目的性又有随机性。
\end{itemize}

以图书馆场景为例，人格差异直接可观测：INTJ-T 的"学霸小明"走进图书馆后，径直走向角落的电脑区（最大探索范围 2 格），在书架间停留较久（移动间隔 9--16s），45\% 的时间站在原地"思考"。与此同时，ENFP-A 的"社交小红"进入同一场景，快速穿梭于各个区域（间隔 3.5--8s，范围 3 格），主动靠近其他 Agent（社交接近权重 25\%），空闲概率仅 10\%，她几乎从不停下来。当两人偶遇时，LLM 根据双方人格实时生成对话：小红热情地分享近况，小明简短回应后继续走向电脑区。情绪引擎同步工作：小红因"图书馆的安静氛围"获得中性情绪微调，小明因"实验数据对上了"的随机事件触发兴奋情绪。

\textbf{成果}：不同人格的 Agent 在相同场景下展现出\textbf{可辨识的行为差异}，内向者安静探索，外向者频繁社交，情绪在对话中起伏，关系在互动中演化，人格参数贯穿了 Agent 的全部行为维度。评测数据显示人格与场景存在显著耦合效应：学霸小明在期末周（高压学术场景）人格一致性最高（45.8），领导者小刚在毕业选择场景交互深度最高（66.4），适应性维度在不同人格间波动显著（78.4--97.7）。

\section{创新二：多 Agent 协作与 Workflow 设计}
%% ============================================================

\textbf{问题}：多 Agent 协作的最大风险是\textbf{"幻觉交付"}，Agent 声称完成了任务，但实际从未执行过关键操作。影响任务质量，动摇用户对 Agent 系统的信任。

\textbf{方案}：Life Lab 实现了从任务分解到交付验收的完整协作链路，支持多 Agent 分工组队完成复杂任务：

\begin{itemize}
	\item \textbf{任务分解}：LLM 将任务拆解为子任务并分配给不同 Agent，LLM 不可用时降级为规则分配（8 种预设角色模板），并执行用户在设计阶段的修改。
	\item \textbf{DAG 管道编排}：支持 DAG 拓扑排序 + 层级并行执行（同层最多 3 路并行），并扩展支持 Loop（回边循环）和 Branch（条件跳转）两种控制流，条件值从节点真实产出文件中读取，支持正则/数值/关键词三种匹配模式。
	\item \textbf{共享工作区}：Agent 间通过文件系统协作，每步自动复制上游产出给下游，确保信息传递可追溯。
	\item \textbf{交付验收}：独立验收员检查 Agent 产出。\textbf{不完全依赖 LLM 判断}，程序直接算一遍算式对不对、查一遍工具调用记录是否真实存在。这些程序级检查的结果强制生效，即使 LLM 验收员判断出错也无法绕过，避免了"验收员和执行者犯同一类错误"的风险。首次不通过时自动退回修订，最多两轮。
	\item \textbf{Worker 状态机}：每个 Worker 通过 6 状态显式状态机管理生命周期，反思阶段可回到决策或规划，形成"执行$\to$验收$\to$修订"的闭环迭代。错误处理采用三级策略：RETRYABLE（自动重试）/SKIPPABLE（Agent 自主决策）/FATAL（立即终止）。
\end{itemize}

以"策划校园科技节"为例，完整协作链路如下：用户提交任务后，LLM 将任务分解为 3 个子任务——"调研往届案例""设计活动方案""撰写预算报告"，分别分配给 3 个 Agent。DAG 引擎分析依赖关系：调研无前置依赖可立即执行，方案设计依赖调研结果，预算报告依赖方案设计。执行过程中，Agent A 通过 web\_search 搜索往届案例并写入 workspace/step\_1.md；验收员检查时发现"调研报告缺少数据来源"，程序级台账核验确认 web\_search 未被调用，判定不通过；Agent A 收到反馈后自动修订，补充搜索并重新提交；验收通过后，产出自动复制到 Agent B 的工作区，Agent B 基于真实文件开始方案设计。整个过程在管线编辑器中可视化呈现，每个节点的状态（执行中/验收中/已完成/修订中）实时更新。

\textbf{成果}：交付可信度从"靠 Agent 自觉"提升到\textbf{"程序直接验证"}。程序直接计算和工具记录核查确保即使 LLM 判断出错，错误仍然会被拦截。5 个团队共执行 14 个计划，验证了任务分解、执行幂等性和交付硬校验等核心特性。

\section{创新三：可量化的行为评测}
%% ============================================================

\textbf{问题}：在非专业任务下，Agent 行为无法跨个体量化比较，"谁的 Agent 更聪明"只能靠主观判断，缺乏客观标准。

\textbf{方案}：Life Lab 基于M1-8的基础平台，构建了系统性的 Agent 行为评测体系：

\begin{itemize}
	\item \textbf{六维雷达评测}：从人格一致性、决策质量、交互深度、鲁棒性、创造力、适应性六个维度打分。其中鲁棒性看的是 Agent 在多次任务中表现是否稳定，用统计中的变异系数（$cv = \sigma/\mu$，即标准差除以均值）衡量：每次得分差不多就满分，忽高忽低就低分。
	\item \textbf{行为一致性量化}：统计 Agent 使用了哪些工具、各用了多少次，用 Shannon 信息熵公式 $C = 1 - H(X)/H_{\max}$（其中 $H(X) = -\sum p(x_i)\log_2 p(x_i)$）计算一致性分数。$C$ 接近 1 说明行为很聚焦（总是用同一种工具），接近 0 说明很分散。这把"人格是否影响行为"变成了可以算出来的数学问题。
	\item \textbf{诊断证据链}：每个维度的分数都有具体证据支撑，比如"思考次数偏少(5次)，内部推理不充分"或"回复长度标准差: 42，能根据情境调整表达方式"。配合决策风格分类（分析型/直觉型/果断型/谨慎型）和劣化趋势检测（对比最近 3 次与前 3 次评测），评测结果不是一个黑箱数字，而是可以看到"为什么这个维度得了这个分"的完整证据链。
\end{itemize}

\textbf{成果}：不同 Agent 的行为模式可以在\textbf{同一尺度}上比较，评测结果完全\textbf{可解释}。4 次完整 Bench 评测（3 Agent $\times$ 3 场景 $\times$ 3 重复 = 27 条/次）积累了 94 条评测子结果，鲁棒性平均 92.8 分（跨场景高度稳定），人格一致性揭示了后续优化方向（平均 32.9 分）。

\section{大模型应用深度与调试优化}
%% ============================================================

Life Lab 通过 OpenAI 兼容 API 统一接入多种大语言模型，评测中使用 \textbf{DeepSeek-V4-Flash}（api.deepseek.com），同时支持 GLM、OpenAI 等模型的无缝切换。

\subsection{模型接入与调用方式}

\begin{itemize}
	\item \textbf{双模式调用}：系统为不同场景配置了"思考"（think）和"行动"（act）两种 LLM 配置，思考模式使用较高温度用于深度推理（如人格铸造、关系评估），行动模式使用较低温度用于快速决策（如工具调用、动作选择）。
	\item \textbf{Prompt 工程}：采用"冻结核心 + 动态上下文"双层 System Message 结构，核心层（身份、价值观、目标）初始化后不变，上下文层（处境、记忆、笔记）每 tick 注入，确保人格一致性与环境感知的平衡。
	\item \textbf{联网搜索}：集成 DeepSeek Responses API 内置联网搜索，并配备搜狗/百度/Bing 多引擎并行兜底，支持断路器保护避免连续失败。
\end{itemize}

以 Worker 决策 Prompt 为例，展示系统的结构化 Prompt 设计：系统向 LLM 发送的决策请求包含当前任务描述、已制定的执行计划、已完成步骤摘要、当前工作区文件列表、上一步操作及结果、可用工具列表。LLM 必须返回严格 JSON 格式，包含 decision（tool\_call / deliverable / done）、tool\_name、tool\_args、reason 四个字段。这种结构化输出设计避免了自由文本解析的不可控性——系统从不在 Prompt 中暴露 JSON Schema 语法（模型容易混淆 \texttt{"a" | "b"} 这类写法），而是通过具体示例引导格式。

\subsection{容错与调试策略}

针对 LLM 系统的固有不稳定性，平台实现了多层次的容错与调试机制：

\begin{itemize}
	\item \textbf{超时重试与指数退避}：所有 LLM 调用包装在统一的异步调用器中，重试间隔采用指数退避（2s、4s、8s），避免对 API 服务造成压力。
	\item \textbf{断路器保护}：联网搜索模块实现断路器机制，连续失败达到阈值后自动断开，避免反复超时拖慢系统。
	\item \textbf{统一错误分类}：通过 LLMErrorClassifier 将上游 OpenAI 兼容异常（AuthenticationError、RateLimitError、TimeoutError、ConnectionError）转换为用户友好的中文提示，方便定位问题。
	\item \textbf{LLM 不可用降级}：任务分解、关系评估等关键路径均有规则兜底方案，LLM 不可用时自动降级为基于关键词/角色的规则引擎，确保系统在任何环境下可用。
	\item \textbf{评测趋势监控}：BenchLab 自动检测评测分数连续下降趋势（对比最近 3 次评测），及时提醒用户可能存在的模型退化问题。
	\item \textbf{JSON 解析重试实战}：在实际运行中，Agent 在反思阶段（REFLECTING）反复输出非 JSON 内容（如"好的，让我继续执行"），导致解析失败。调试发现原因是 Prompt 中的示例过于简短，模型在长上下文中容易"忘记"格式要求。解决方案：在 JSON 解析失败时，系统自动追加格式提示（包含完整示例），并在最多 3 次重试后强制将 Agent 推进到下一步，避免死循环。这一机制使 Worker 的 JSON 解析成功率从约 85\% 提升到 98\% 以上。
\end{itemize}

\section{应用场景与推广价值}
%% ============================================================

Life Lab 的独特能力——人格驱动行为、可信赖协作、可解释评测——使其不仅是一个技术平台，更是一个能真正帮助学生成长的工具。

\subsection{个性化成长指导}

一个迷茫的大二学生面对"要不要转专业"的抉择：打开 Life Lab，创建一个"理性务实的 ESTJ 学长"和一个"感性包容的 ENFP 学姐"，分别向它们倾诉困惑。ESTJ 学长会直接列出转专业的利弊清单、就业率数据，给出果断建议；ENFP 学姐会先共情她的焦虑，分享自己探索兴趣的经历，引导她自己想清楚。两个 Agent 的建议风格完全不同，但都基于各自的人格参数，真正拥有不同决策风格（分析型 vs 直觉型）的 AI 角色。学生可以在 Life Lab 中同时咨询多个不同人格的 Agent，获得多元化的视角，最终自己做出判断。

\subsection{AI 同伴社交模拟}

当多个具有不同性格的 Agent 被放入同一校园场景，会自然涌现出小团体、意见领袖、冲突与和解：这帮助学生直观理解"不同性格的人如何相处"。学生可以观察：内向的 Agent 如何在小范围内建立深度关系，外向的 Agent 如何成为社交中心，不同决策风格的 Agent 面对同一事件如何做出截然不同的选择。这种可重复、可量化的社会模拟，为心理学和人际交往提供了全新的实验视角。

\subsection{可信赖的多 Agent 协作}

学生还可以让多个 Agent 组队完成复杂任务——如"策划校园科技节"：一个 Agent 负责调研往届案例，一个负责设计活动方案，一个负责撰写预算报告。所有交付由程序直接验证（算式直接算一遍、工具记录直接查一遍），不存在"Agent 声称做了但实际没做"的幻觉。首次不通过时自动退回修订，最多两轮，确保每一步都真正执行。

\subsection{AI 人格实验与教学}

Life Lab 提供了从"铸造人格 $\to$ 投放场景 $\to$ 观察行为 $\to$ 量化评测 $\to$ 调整优化"的完整闭环，使抽象的 AI 概念（人格建模、行为涌现、多智能体协作）变得可感知、可实验。不同大语言模型（DeepSeek、GLM、GPT 等）在相同人格设定下的行为差异，也可以通过六维雷达和行为一致性分数进行量化比较——传统基准测试只能衡量"答题能力"，Life Lab 揭示的是"行为风格"。

\section{总结}
%% ============================================================

大多数 Agent 项目止步于"让 Agent 完成任务"。Life Lab 关注的是一个旁路但重要的问题：\textbf{当 Agent 拥有了性格、情绪和同伴，它们会怎样？}

七个阶段、12 个模块的持续迭代，Life Lab 构建了三项其他框架不具备的能力：\textbf{人格直接决定行为}（MBTI 贯穿对话/移动/情绪全链路）、\textbf{程序直接验证交付}（DAG 管道编排 + AST 硬校验 + 自动修订闭环）、\textbf{基于信息论和统计学的量化评测}（六维雷达 + 信息熵指纹 + 变异系数鲁棒性）。这三项能力使 Life Lab 从"有趣的 Agent 玩具"跃升为"可量化、可编排、可涌现的 Agent 社会实验平台"。

平台在实际运行中积累了 \textbf{94 条评测子结果}，鲁棒性维度平均得分 \textbf{92.8 分}（跨场景高度稳定），为模型行为分析提供了可量化的实验基础。系统支持 DeepSeek / GLM / OpenAI 多种大模型，通过 OpenAI 兼容 API 统一接入，内置超时重试、断路器与降级兜底，确保在任何环境下可用。

Life Lab 不只是一个竞赛作品，它是一个研究者和学生可以真正用来探索 AI 社会性行为的工具。人格可以被铸造，行为可以被观测，涌现可以被量化，协作可以被信赖。这是 Life Lab 与其他 Agent 项目最本质的区别。
