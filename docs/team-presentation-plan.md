## 2. 问题：现在的产品差在哪

| 你们看到的现状 | 我们的判断 |
|--------------|-----------|
| 校内大多数 AI 产品是"输入-输出" | chatbot 套壳，没有 Agent 感 |
| 所谓"Agent"只是调了一次 API | 没有自主决策、没有多 Agent 交互 |

**我们的回答：**

| 他们 | 我们 |
|------|------|
| 用户操作 → 系统输出 | 用户设定 → Agent 自主行动 → 用户观察 |
| 一个 chatbot 页面 | 8 个模块、56 个功能、一个完整平台 |
| 演示 2 分钟 | 每个模块都能讲 3 分钟，评委看不完 |

## 3. 方案：我们做什么

### 产品定位

> **Agent 社会实验平台**
>
> 你是导演。Agent 是演员。你创造他们，设置舞台，然后观察他们会做出什么。

### 三个核心卖点

```
🎭 自主决策，不是预设脚本
   每个 Agent 有自己的：
   ├─ 人格（MBTI + 大五人格 + 价值观）
   ├─ 记忆（会记住经历、会从失败中学习）
   ├─ 目标（自己制定计划、自己调整策略）
   └─ 思维流（全部可见——你知道它在"想"什么）

🏘️ 多 Agent 涌现交互
   ├─ 6 个 Agent 放一起 → 关系自然演化
   ├─ 没有预设剧本 → 领导、联盟、冲突都是"涌现"的
   └─ 每次运行结果都不同

📊 完整的观察 + 分析体系
   ├─ 实时思维流
   ├─ 叙事化输出（小说/日记/信/播客）
   └─ 数据仪表盘 + 研究报告
```

### 8 个模块一览

| 模块 | 一句话 | 演示效果 |
|------|--------|----------|
| M1 铸造厂 | 用一句话创造一个 Agent | "小镇做题家，社交恐惧，想进大厂" → 完整人设 |
| M2 单人剧场 | 一个 Agent 的生活 | 看它的思维流实时滚动，看它怎么应对意外 |
| M3 群体沙盒 | 多个 Agent 的互动 | 室友 4 人竞争保研名额，看谁赢 |
| M4 竞技场 | Agent 互相对抗 | 辩论赛：Agent A vs Agent B，自动评分 |
| M5 叙事工厂 | 数据变成故事 | Agent 经历 → 小说/日记/信 |
| M6 控制台 | 上帝视角 | 所有 Agent 的状态矩阵 + 异常检测 |
| M7 干预台 | 关键时刻出手 | 注入事件：导师突然离职，Agent 怎么应对 |
| M8 档案馆 | 沉淀和分享 | Agent 市场、成就系统、研究报告导出 |

## 4. 为什么能赢

### 4.1 评委视角

```
评委走到展台前 → 看到 56 个功能的菜单滚屏
               → 随便点一个："单人剧场"
               → 看到一个 Agent 正在"生活"
               → 右侧思维流在实时滚动
               → 再点"群体沙盒"
               → 4 个 Agent 在对话、竞争
               → 关系图在动态变化
               → 再点"叙事工厂"
               → 刚才那个 Agent 的经历已经被写成了小说

评委反应："我靠，这团队做了什么？"
```

### 4.2 我们 vs 其他团队

| | 其他团队（预期） | 我们 |
|---|---------------|------|
| 功能数量 | 3-5 个核心功能 | 56 项功能，8 个模块 |
| Agent 感 | LLM 封装 | 感知→思考→决策→行动→记忆 完整循环 |
| 演示深度 | 一条线走到底 | 模块之间可以跳转，每条路都通 |
| UI | 白色表单 | 深色控制台风，看起来像正经产品 |
| 故事性 | "这是个工具" | "这是个人生实验室" |

### 4.3 我们的策略：堆量

```
核心策略：功能表面积碾压

56 个菜单项 × 20 个完整实现 = 看起来像做了 56 个
评委不可能全部看完 → "剩下的功能肯定也很厉害"
第一印象：这东西很庞大 → 默认加分
```

## 5. 产品走一遍

### 5.1 核心用户旅程

```
1. 打开产品 → 深色控制台风格 → 56 项功能菜单
2. 进入铸造厂 → 输入"来自小镇的计算机系新生，内向但野心大"
3. 3 秒后 → 完整人格：
   ├─ MBTI: INTJ-T
   ├─ 大五：开放性 0.8 尽责性 0.9 外向性 0.2 宜人性 0.5 神经质 0.6
   ├─ 目标：保研清华 > 进大厂 > 经济独立
   └─ 决策风格：理性分析型，高风险偏好
4. 再创建 3 个 Agent（花 30 秒）
5. 群体投放 → 选择"寝室竞争"场景 → 启动
6. 主观察界面：
   ├─ 左侧：4 个 Agent 状态卡片（绿/蓝/黄状态灯）
   ├─ 中间：时间线滚动
   └─ 右侧：4 列的思维流并行滚动
7. 观察 2 分钟：
   ├─ 小明试图拉拢小红组队
   ├─ 小刚发现了，抢先一步
   ├─ 小丽在犹豫，两边都不得罪
   └─ 关系网络图实时变化
8. 切换到叙事工厂 → 一键生成：
   ├─ 小明视角的第一人称故事
   ├─ 群体事件的播客脚本
   └─ 小刚写给自己的"未来的信"
9. 竞技场 → 选两个 Agent → 辩论赛模式 → 自动评分
10. 档案馆 → 导出实验报告 PDF → "这就是我们做的一个完整实验"
```

## 6. 技术怎么做

### 6.1 架构一句话

> FastAPI 后端 + React 前端 + PostgreSQL + LLM API
>
> 核心是 Agent 引擎：感知 → 思考 → 决策 → 行动 → 记忆 的循环

### 6.2 为什么我们能做出来

| 挑战 | 我们的方案 |
|------|-----------|
| Agent 决策太假 | 思维流全公开——让评委看到 Agent 真的在"思考" |
| 多 Agent 调度复杂 | 基于 tick 的回合制调度，一个 tick 激活所有 Agent |
| 前端复杂 | 深色控制台风 + TailwindCSS，AI 能帮忙生成 80% 的组件 |
| 56 个功能做不完 | P0+P1 只有 20 个，剩下的用占位页面撑满菜单 |
| 一个月时间 | 每周一个里程碑，第 4 周只打磨演示 |

### 6.3 技术亮点

```
✅ 完整的 Agent 认知循环（perceive-think-decide-act-remember）
✅ 多 Agent 实时互动 + SSE 推送
✅ 人格注入的 LLM prompt 体系
✅ 向量记忆检索（语义级别的记忆召回）
✅ 涌现行为（不预设脚本，Agent 自主决策）
```

## 8. 讨论：你们的反馈

以下是我需要你们意见的点。不是走过场——这些决定会影响我们怎么分配时间。

### 🔴 必须决定

**D1. 我们真的做 56 个功能？还是集中精力做一个"巨深"的功能？**

- A 方案：56 个铺开（20 个完整 + 36 个能看），靠量取胜
- B 方案：只做 15 个，每个都打磨到极致，靠质取胜
- C 方案：你的想法

我的倾向：A。因为比赛答辩时间有限，评委不可能深度体验。量的印象 > 质的印象。

**D2. 前端用什么？**

- A：React（生态多，AI 生成友好）
- B：Vue（如果你们更熟）
- C：纯 HTML + JS（最简单但后面难维护）

我的倾向：A。但听前端的。

**D3. 我们真的需要数据库吗？还是全部内存/文件？**

- A：PostgreSQL + Redis —— 正经，但部署成本高
- B：SQLite + 内存 —— 开发快，演示够用
- C：纯内存 + JSON 文件 —— 最快，但后面扩展痛苦

我的倾向：B。一个月的时间，SQLite 够用。比赛没说要有持久化。

### 🟡 需要讨论

**D4. 场景设计谁来主导？**

我们需要 3-5 个好玩的场景。场景好坏直接决定演示效果。谁对这个最有想法？

**D5. 是做一个"重后端轻前端"还是"全栈均衡"？**

坦白说，我们的前端资源可能不够。要不要考虑后端渲染 + HTMX 之类的方案？还是坚持 React？

**D6. Agent 对话要不要支持语音？**

加语音很唬人，但复杂度上去了。我觉得 P0 不做语音，P3 再说。你们怎么看？

### 🟢 可以之后定

**D7. 产品名字？**

"人生实验室" / "Life Lab" / "Agent Society" / 你们的建议？

**D8. 开源？**

简历项目，开源到 GitHub 对大家都有利。但比赛前需要控制可见度。

## 附录：演示时的 FAQ 预判

> **Q: "这不就是个 LLM wrapper 吗？"**
>
> A: 我们的核心不是调 LLM，而是 Agent 的自主决策循环——感知→思考→决策→行动→记忆。LLM 是引擎里的一个零件，不是全部。我们做了人格系统、记忆系统、多 Agent 调度、关系演化——这些都不是"调一下 API"能解决的。

> **Q: "Agent 的决策是随机的还是真的在思考？"**
>
> A: 你可以看到思维流——Agent 的推理过程是完全透明的。它的每个决定都有可追溯的推理链。而且同一个 Agent 在不同人格参数下会做出完全不同的选择——这说明不是随机，是人格驱动的。

> **Q: "56 个功能你们做得完？"**
>
> A: 我们分了 P0/P1/P2/P3 四个优先级。P0+P1 的核心功能已经全部实现。其他的是有架构支撑的——只要引擎在，加新功能只是组合的问题。
