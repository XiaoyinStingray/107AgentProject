# Life Lab 演示脚本

> 对应 Step 28 / development-plan.md §9.3。默认使用前端 Mock 主链路，确保无 LLM、无后端时也能稳定演示；真实 API 只做独立健康检查。

## 1. 演示目标

- 在 5 分钟内说明 Life Lab 的核心价值：创建 Agent、观察群体互动、生成叙事、进行竞技并导出结果。
- 展示 M1–M8 共 56 项功能菜单，以及 P0–P3 的实现层级。
- 明确区分 Mock 展示与真实 API，避免把尚未联通的能力描述成端到端功能。

## 2. 演示环境

### 必要条件

- Python 3.12 或更高版本。
- Node.js 与 npm 可用。
- 已执行 `pip install -r requirements.txt`。
- 已在 `frontend` 目录执行 `npm.cmd install`。
- 推荐浏览器窗口使用 1920×1080；最低走查宽度为 1280px。

### 数据源说明

| 演示模块 | 默认数据源 | 是否依赖后端/LLM |
|----------|------------|------------------|
| Dashboard | 前端 Mock | 否 |
| M1 铸造厂 | Mock Agent Builder | 否 |
| M3 群体沙盒 | Mock SSE | 否 |
| M4 竞技场 | 三模式确定性 Mock | 否 |
| M5 叙事工厂 | Mock 叙事库 | 否 |
| M8 报告导出 | Agent Mock 报告 | 否 |
| `/health` | FastAPI | 需要后端，不需要 LLM |

## 4. 五分钟正式演示

### 0:00–0:30｜开场：Dashboard

操作：打开 `/`，停留在 Dashboard。

讲解：

> 这是 Life Lab，一个 Agent 社会实验平台。我们不只让 Agent 回答问题，而是给它人格、目标、关系和场景，观察它在长期互动中如何做决定。

画面重点：

- 八个模块快捷入口。
- 最近 Agent 卡片。
- 深色实验室视觉风格。

### 0:30–1:30｜M1 铸造厂：创建 Agent

操作：

1. 进入“M1 铸造厂”。
2. 依次输入以下描述并点击“创建 Agent”：
   - `来自小镇的计算机系新生，内向、谨慎，但希望证明自己。`
   - `擅长社交的校园活动组织者，乐观，重视朋友关系。`
   - `目标感极强的商科学生，竞争意识强，做事果断。`
3. 点击已创建列表，展示人格、背景、价值观和决策风格。

讲解：

> 用户只输入一句自然语言，系统就能得到结构化人格。今天的稳定演示使用同接口的 Mock 数据，真实后端对应 Persona Builder 和 AgentFactory。

预期结果：三个 Agent 均进入当前会话 Store，切换页面后仍可选择。

### 1:30–3:00｜M3 群体沙盒：观察互动

操作：

1. 进入“M3 群体沙盒”。
2. 保留至少两个 Agent，选择“期末周”。
3. 点击“开始模拟”。
4. 将速度切换到 2×。
5. 展示 Timeline、Event Feed、Thought Stream 和 Relationship Graph。
6. 暂停一次，再点击“继续”，证明继续不会重置事件流。

讲解：

> 同一场景下，不同人格会形成不同决策。中间是事件时间线，右侧是思维流，上方关系图会根据互动逐步变化。

预期结果：事件逐条出现，暂停后停止增长，继续后从原位置恢复。

### 3:00–3:30｜M5 叙事工厂：事件变故事

操作：

1. 进入“M5 叙事工厂”。
2. 选择一个 Agent。
3. 选择“小说”或“日记”。
4. 点击“生成叙事”。
5. 展示结果，并指出复制、重新生成和 Markdown 下载。

讲解：

> 同一批模拟事件既可以作为研究数据，也可以转化为小说、日记、信件或播客脚本。

### 3:30–4:00｜M4 竞技场：Agent PK

操作：

1. 进入“M4 竞技场”。
2. 选择两个不同 Agent。
3. 选择辩论、面试或路演模式。
4. 使用预设主题或编辑自定义主题。
5. 点击“开始 1v1 竞技”。
6. 等待三轮对话、裁判评分和结果页。

讲解：

> 竞技场比较的不是单一答案，而是论点、表达、应变和人设一致性。裁判只在双方完成对抗后统一评分。

预期结果：六条发言后进入裁判阶段，最终显示胜者、四维评分和裁判理由。

### 4:00–4:30｜56 项功能菜单

操作：

1. 从 M1 滚动到 M8，展示全部菜单。
2. 点击一个 P1/P2 项，展示当前功能提示和模块页面。
3. 点击一个 P3 项，展示统一“建设中”页面。
4. 返回模块标题，继续下一段。

讲解：

> 56 项功能按优先级铺开。P0/P1 是核心体验，P2 提供可扩展骨架，P3 保留产品路线入口。

### 4:30–5:00｜M8 档案馆：导出报告

操作：

1. 进入“M8 Agent 档案馆”。
2. 切换到“研究报告导出”。
3. 选择“Agent 数据（Mock）”。
4. 选择一个 Agent 和 Markdown 格式。
5. 点击“导出报告”，确认浏览器开始下载。

讲解：

> 最后，实验过程可以沉淀为可分享、可复盘的研究报告。当前演示使用 Agent Mock 报告；后端也提供基于 World 事件的 Markdown 和 JSON 导出 API。

## 5. 故障降级

| 问题 | 现场处理 |
|------|----------|
| `127.0.0.1` 拒绝连接 | 确认前端终端仍显示 Vite ready，再刷新页面 |
| 后端 8000 未启动 | 跳过 `/health`；主演示继续使用 Mock |
| LLM Key 不可用 | 不切换真实 Agent/竞技调用，保持 Mock 主链路 |
| Agent 创建按钮无响应 | 等待当前 1.5 秒 Mock 完成；不要连续重复点击 |
| 沙盒事件播放完毕 | 点击“重置”，重新选择场景并开始 |
| 下载被浏览器拦截 | 允许当前站点下载后重试 |
| 页面布局异常 | 恢复浏览器 100% 缩放，使用 1280px 以上宽度 |

## 6. 演示边界

- 前端真实 SSE 与现有展示事件仍需要适配层，本次主演示使用 Mock SSE。
- ArenaEngine 尚未暴露 `/api/arenas`，竞技场主演示使用前端 Mock。
- 叙事页面尚未连接后端 NarrativeEngine，主演示使用 Mock 叙事库。
- M7 干预事件与群体沙盒尚未共享运行状态。
- 成就系统当前展示静态 Mock 进度。
- 不把上述能力描述为已经完成的真实端到端联调。
